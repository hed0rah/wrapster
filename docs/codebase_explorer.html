Data flow: three MCP transports

All three transports share handleMessage and gateMethod. The state machine enforces CONNECTED to INITIALIZING to READY before any tool call is dispatched.

fig. 1: all three transports funnel through gateMethod then handleMessage; tools/call dispatches concurrently in stdio and SSE, synchronously in streamable HTTP (net/http handles concurrency there)

Data flow: a command through the security stack

Every command, regardless of transport, passes through the same ordered checks. Hard denies run first on a fused DFA, then mode-specific policy, then the filter chain.

fig. 2: SSH exec uses allowlist mode; local exec uses guardrail by default. hard denies are unconditional in both modes. the filter chain catches exploit classes policy cannot enumerate by name.

Policy system deep dive

Two validation modes

  • Guardrail mode (local execution default): every command passes unless it hits a hard deny, a denied_patterns entry, or a filter finding. The filter chain is the primary safety net. Shell operators are automatically allowed in guardrail mode so LLMs can use pipes and redirects.
  • Allowlist mode (all SSH execution): every command must match at least one allowed_commands rule. A CommandRule can specify an exact command plus an optional args_pattern regex, or a full-line regex in pattern. Unmatched commands are denied by default.
  • Segment splitting closes the chain injection hole: when allow_shell_operators: true, each operator-separated segment must independently match a rule. An allowlisted uptime cannot drag ; curl attacker.com through with it.
  • Command substitution ($(), backticks, <()) is unconditionally blocked in allowlist mode because it embeds a sub-command that cannot be validated per-segment.

Hard denies

  • hardDenyFused alternates all 10 individual patterns into one compiled regex so a single DFA pass answers "does any dangerous pattern match?" instead of running 10 sequential MatchString calls. The slow-path individual rules only run when fused fires, to name which one triggered.
  • Patterns include: rm -rf / in any short-flag order, dd of=/dev/*, raw disk writes, mkfs, fork bomb, /etc/passwd|shadow|sudoers, chmod 777, world-writable symbolic, and download-pipe-to-interpreter. These are unconditional in both modes.
  • Destructive-filter patterns intentionally omit the hard-deny cases to avoid redundant matching; policy runs first and would already have blocked them.

Policy resolution

  • ResolvedPolicy merges defaults with the host-specific overrides. It deep-copies every reference-typed field (maps and slices) so a resolved HostPolicy never aliases the shared defaults. This matters because tools/call dispatches concurrently and multiple hosts could resolve simultaneously.
  • Allowed commands from defaults and host are appended, not replaced, so a default uptime rule is available on every host.
  • The Duration type wraps time.Duration with custom YAML marshal/unmarshal because yaml.v3 has no native duration support and would emit raw nanoseconds, breaking the documented "30s" policy format.

Filter chain deep dive

GTFOBins knowledge base

  • The embedded gtfobins.json is a structured form of the GTFOBins project: binaries with named techniques and code examples. codeToPattern converts each code example into a targeted regex by matching known indicators (e.g. pty.spawn, /bin/sh, -e /bin/bash).
  • GTFObinsFilter.Scan applies universal patterns first (which catch exploit classes regardless of binary), then per-binary rules keyed on the extracted first token of the command. A seen map deduplicates findings when the same raw pattern fires twice.
  • regexp.MustCompile is used throughout the filter modules for all compile-time constant patterns. A bad pattern is a programmer bug; panicking at startup is preferable to silently dropping a security rule.

Exfil filter and RE2 workaround

  • RE2 (Go's regex engine) has no negative lookahead. Rules like "curl to a non-local host" cannot be expressed as a single regex. ExfilFilter.Scan instead uses a match-then-post-filter pattern: capture the destination host from the command, then call isLocalHost in Go to decide.
  • urlDestPattern captures the hostname from curl/wget/fetch URLs. sshDestPattern captures the host from scp/rsync destination. dnsTxtPattern captures the resolver from dig TXT @resolver. All three are post-filtered.
  • RFC 1918 addresses (10.x, 172.16-31.x, 192.168.x) are treated as local so routine internal administration is not flagged as exfiltration.

Output pipeline and bufstore

  • StripANSI first does a byte scan for ESC (0x1b); if none present it returns the string unchanged without ever touching the regex. Only when ESC is found does ansiPattern run. This makes clean output (the common case) essentially free.
  • The truncator uses a ring buffer of newline offsets to find the tail section without splitting the string into lines first. It walks bytes once, tracking head-end and the last (tail+1) newline positions simultaneously.
  • When output is truncated, BufStore stores the full pre-truncation content under a random 8-hex buf_id. The tool result includes a resource content block with URI buf://<id> so the model can fetch the remainder via resources/read or search it with grep_output.
  • BufStore evicts the oldest entry when the 64-entry limit is hit. Slice(id, offset, length) supports offset+length paging for large buffers. crypto/rand failure panics rather than producing colliding zero-value IDs.

Config wizard (wrapster config)

  • The bubbletea model presents a 7-item menu (local, filters, output, hosts, save, MCP registration, quit) with a 55/45 split layout: left pane shows the active form or menu, right pane shows a live YAML preview rendered by policyio.MarshalYAML.
  • huh forms bind directly to policy fields. Form values that huh cannot bind (strings for durations, comma lists for commands) use scratch fields that are converted on form completion. Aborting a local/filters/output form still marks the policy dirty because huh binds fields live before abort is detected.
  • Registration reads the existing config file, merges via Merge/MergeNested, and writes atomically. A genuine missing file starts fresh; any other read error aborts to avoid overwriting a config that simply failed to read. A timestamped .bak is written before any overwrite.
  • Client registry lists 7 MCP clients. VS Code is the outlier: it uses Key: "servers" instead of "mcpServers" and is project-scoped to .vscode/mcp.json. Claude Code uses its CLI (claude mcp add-json) when available, bypassing direct file surgery on the nested .claude.json structure.
